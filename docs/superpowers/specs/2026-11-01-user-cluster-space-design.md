# 用户分簇三维观测界面设计

## 目标

新增一套独立的三维观测界面，以用户为数据簇、以商品类别为点的颜色，并用半透明红黄绿细线连接可对比分析的数据点。原 `/space` 分类时空界面及其逻辑保持不变。

## 方案比较

- 在原页面增加布局模式：可复用较多控件，但会让两套空间语义、图例和状态互相耦合，不采用。
- 用 iframe 包装新页面：隔离较强，但导航、会话和测试路径更复杂，没有实际收益，不采用。
- 新增 `/user-space` 独立页面和布局模块，复用现有数据接口、筛选、自动配对、最小树及判定规则：边界清晰且避免重复分析逻辑，采用此方案。

## 页面与导航

新增 `/user-space`，返回 `user-space.html`，使用本地 Three.js 与 `obs_api_key` 管理员会话，数据仍来自 `/api/space/points`。原三维页与新页面互相提供导航链接。新页面提供平台、类别、用户和商品搜索筛选，以及刷新、演示数据、比较图层开关、用户标签开关、点选详情和商品组隔离。

## 用户锚点与簇内布局

新增 `user-space-layout.js`，导出 `buildUserClusterLayout(points)` 和 `categoryColor(category)`。

- 每个非空 `user_pseudonym` 对应一个数据簇；空值归入“未知用户”。用户锚点由用户名的哈希播种，在半径 70–140 的三维空间内确定方向与高度。锚点是确定性伪随机结果，同一用户刷新后位置不变，不引入随机状态或额外依赖。
- 类别颜色由一级类别哈希到固定调色板；空类别使用中性灰。相同类别始终同色，与空间位置无关。
- 簇内 X 偏移来自全数据集的 `log1p(normalized_price_cents)` 归一化结果，Y 偏移来自 `log1p(discount_coupon_amount_cents)` 归一化结果，Z 偏移来自 `fetch_ts` 时间归一化结果。缺失数值或无效时间落在对应轴的中性位置。
- 为避免相同数值的点完全重叠，在三个轴上加入由观测 ID、平台、城市、会员和设备字段共同播种的小幅确定性偏移。连续字段决定主要局部分布，其他字段只影响有限范围内的小偏移，所有点保持在所属用户锚点附近。
- 布局基于完整已加载数据计算一次，筛选只改变可见性，避免筛选时用户锚点或已有数据点跳动。布局不修改输入点。

## 比较细线

复用 `buildAnalyzableComparisonGroups`，仍按同商品、中位价价差最大的两位匿名用户自动配对。复用 `buildComparisonGeometry` 对每个商品组的两组点生成一棵最小树，复用 `comparePriceGroups` 得出红黄绿结论。

每条非零长度树边使用两端点的 `THREE.BufferGeometry`、`THREE.LineBasicMaterial` 和 `THREE.Line`，透明度为 0.45，不创建圆柱、球簇或粗线网格。点击商品后仅保留该商品组；比较图层开关只影响比较线。现有配对、阈值和最小树算法不改。

## 视觉与交互

用户簇不添加包围球或圆柱，仅显示散点和可切换的用户名标签。点使用类别颜色，比较线使用现有红黄绿色值。支持拖动旋转、滚轮缩放、右键平移、点击点查看详情、点击空白取消商品隔离。空数据、无效坐标、无真实数据时的演示模式和接口错误均有明确状态。

## 测试

- 布局单元测试覆盖锚点确定性、用户独立性、类别配色、连续字段对局部坐标的影响、小偏移有界、无效字段和输入不变性。
- 页面测试覆盖新路由、双向导航、本地 Three.js、复用分析模块、原生半透明细线、无圆柱／球簇以及 JavaScript 语法。
- 浏览器实测使用临时网络夹具构造红黄绿三组，检查四个用户簇、类别颜色、21 条原生最小树细线、图层开关、商品点选隔离和接口／演示状态；临时服务与文件在验证后清理。
- 运行完整 Python 与 JavaScript 测试。所有改动提交 Git，仅同步本地预览，不部署线上。
