# 商品分类与高维可视化设计

日期：2026-10-29

## 目标与约束

为现有“算法歧视众包观测”系统增加商品级大模型分类、稳定缓存、观测点计算和高维可视化能力。

- 不修改 `observations` 等现有表的字段，不改变金额单位、原币保存、UTC 时间和匿名规则。
- 大模型只负责商品分类，不生成用户关系、价格关系或歧视判断。
- 分类输入仅限 `product_name`、`seller_id`、`product_url`、`platform_code`。
- DeepSeek 密钥仅由服务端环境变量读取，不进入仓库、浏览器响应或日志。
- 本次只改服务端与管理页面，插件版本保持 1.1.0。

## 方案

新增独立的商品分类缓存表、分类服务、可视化点服务和专用管理页面。现有观测记录保持原样；分类按商品维度完成，观测点在请求时由观测、分类和汇率组合生成。

不采用浏览器直接调用大模型（会暴露密钥且缓存不稳定），也不把分类字段写回观测（会重复存储并改变现有数据结构）。

## 商品身份与缓存

对每个商品使用两种键：

- `product_key`：对 `platform_code`、`product_id`、`seller_id || ""` 的规范 JSON 数组计算 SHA-256，输出完整十六进制摘要。同一商品改名时该键不变。
- `cache_key`：对 `platform_code`、`product_id`、`seller_id || ""`、`product_name` 的规范 JSON 数组计算 SHA-256。名称变化会形成新的分类版本，避免沿用旧名称的分类。

处理前先按需求规定的 `platform_code + product_id + seller_id + product_name` 去重。每个 `cache_key` 至多调用一次模型；同一商品的多条观测复用同一分类结果。

新增 `product_category_cache` 表，与现有观测表无外键和字段耦合，保存：

- `cache_key` 主键；
- `product_key`、平台、商品 ID、卖家 ID、商品名、商品链接；
- 一级、二级、三级分类；
- 置信度、证据片段、人工复核标记；
- 模型名、创建时间和更新时间。

该表只新增缓存，不 redesign 或迁移任何既有字段。缓存命中时不调用模型。临时网络错误、无效模型响应不持久化，以便后续重试；确定的信息不足结果可以缓存。

## DeepSeek 分类服务

新增 `product_categories.py`，职责限于商品去重、提示词构造、HTTP 调用、响应校验和缓存。

配置：

- `DEEPSEEK_API_KEY`：必填，未配置时使用降级分类；
- `DEEPSEEK_BASE_URL`：默认 `https://api.deepseek.com/v1`；
- `DEEPSEEK_MODEL`：默认 `v4.1flash`，可由部署环境覆盖；
- 请求使用 OpenAI 兼容的 `/chat/completions`，短超时，要求 JSON 输出。

每个未缓存的去重商品调用一次模型。请求体只包含允许的四个商品字段和固定分类体系，不包含用户身份、地址、设备、登录状态、会员、新用户状态或其他观测环境。

模型返回对象包含：

- `product_key`、`product_id`、`seller_id`；
- `category_l1`、`category_l2`、`category_l3`；
- `confidence`、`evidence`、`needs_human_review`。

服务端不信任模型生成的身份字段，而是以输入重新计算并覆盖 `product_key`、`product_id`、`seller_id`。同时校验：

- 一级分类及一级/二级组合必须属于固定分类体系；
- 三级分类无法判断时为空字符串；
- 置信度必须为 0 到 1 的有限数值；
- 证据必须是商品名中不超过 40 个字符的片段；
- 置信度小于 0.75 时强制 `needs_human_review=true`；
- 一级分类为“其他／无法判断”时强制人工复核；
- 商品名过短或明显无有效信息时，不调用模型，直接返回“其他／无法判断 / 无法判断”、置信度 0、需人工复核。

模型未配置、请求失败、返回非 JSON 或字段不合法时，当前请求使用同样的降级结果，不阻断可视化；临时失败不写缓存。

## 可视化点计算

新增 `visualization.py`，输入观测 ORM 对象、对应分类和同一批次汇率结果，输出需求规定的完整点字段。

### 价格和币种

- `display_price_cents is not None` 时采用展示价并标记 `price_basis="DISPLAY"`；否则采用到手价并标记 `ACTUAL`。
- CNY：`normalized_price_cents=basis_price_cents`，`exchange_rate=1.0`，`exchange_stale=false`。
- USD：每批请求复用现有 `latest_rate` 获取一次 USD/CNY；使用 `Decimal` 和四舍五入将基准价格折算为人民币整数分。
- 使用最近成功汇率时，保留其汇率和实际日期并设置 `exchange_stale=true`。
- 完全无可用汇率时，USD 点的折算价、汇率和日期为 `null`，页面仍可展示原币值；该点不参与价格差关系计算。
- 其他币种的折算价、汇率和日期均为 `null`，只能展示原始值。
- 原始 `display_price_cents`、`actual_pay_price_cents` 和 `currency` 不改写。

### 时间、匿名与证据

- `fetch_ts` 输出带时区的 UTC ISO 8601；数据库返回 naive datetime 时按 UTC 解释。
- `user_ref` 非空时，`user_pseudonym="u_"+sha256(user_ref)[:10]`；老数据无 `user_ref` 时输出 `null`，不把多条未知用户记录合并成同一假名。
- 点数据及接口元数据均不返回原始 `user_ref`。
- `has_screenshot` 和 `has_dom_snapshot` 只根据对应路径是否非空计算，不代表文件已上传。

### API

新增管理员鉴权接口：

`GET /api/analysis/visualization-points`

支持按平台、一级分类、币种、商品 ID 过滤。分类过滤在分类组装后进行，其余过滤尽量下推到数据库。响应包含：

- `points`：每个符合过滤条件的观测一个点；
- `classifications`：本次涉及的去重商品分类结果，包含完整三级分类与复核字段；
- `meta`：总数、折算价可用数、降级分类数、汇率信息及警告。

接口复用现有 `X-API-Key` 管理员鉴权，同步计算放入线程池，避免阻塞事件循环。

## 高维可视化页面

新增 `/visualization` 独立管理页面，并从现有控制台侧边栏和统计分析页提供入口。页面复用本地保存的管理员密钥，不向浏览器暴露 DeepSeek 配置。

页面包含：

- 平台、一级分类、币种过滤及刷新按钮；
- 以采集时间为 X 轴、人民币折算价为 Y 轴的散点图；
- 一级分类颜色编码、平台形状编码，形成时间、价格、分类、平台四个维度；
- 鼠标悬停显示商品、稳定用户假名、卖家、原始价格、折算价格、汇率状态、促销、会员、新用户、设备、城市和库存等信息；
- 分类汇总与需人工复核数量；
- 原始点表，便于核对价格基准、原币金额和证据标记。

`normalized_price_cents=null` 的点不进入折算价散点图，但保留在点表并计入警告。页面只展示字段计算结果，不生成新的歧视关系结论。图形使用原生 SVG/JavaScript，不新增前端运行时依赖。

## 错误处理

- 无管理员凭证：接口返回 401/403，页面提示输入密钥。
- 模型不可用：分类降级并明确提示需人工复核，观测点仍返回。
- 单个模型响应无效：仅该商品降级，不影响其他商品。
- 汇率源失败但有缓存：使用缓存并显示“最近成功汇率”及日期。
- 汇率完全不可用：折算字段置空，不混算、不硬编码汇率。
- 空数据：页面显示空状态，不渲染误导性图表。

## 测试与验收

新增测试覆盖：

1. 商品稳定键与缓存键稳定、名称变化只改变缓存键。
2. 多条观测先按商品去重，每个未缓存商品只调用一次模型，缓存命中零调用。
3. 模型请求只含允许的四个商品字段，不含任何用户环境字段。
4. 合法分类解析、非法 JSON/分类/置信度/证据降级、低置信强制复核、短名称不调用模型。
5. CNY、USD、最近成功汇率、无汇率和其他币种的点计算。
6. 展示价优先、到手价回退、UTC、稳定假名、无原始 UUID、证据路径布尔标记。
7. API 鉴权、过滤、分类输出和完整点字段。
8. 页面入口、脚本语法、空折算值排除和原始值展示。

运行完整单元测试。所有外部模型和汇率请求在测试中替换为可控假实现，不依赖真实密钥或网络。

## 非目标

- 不修改现有价格歧视统计阈值或因果判断方法。
- 不让大模型判断用户、价格或歧视关系。
- 不支持 USD→CNY 之外的汇率换算。
- 不上传截图或 DOM 文件，不修改插件采集逻辑。
- 不在仓库或部署文档中保存真实 API 密钥。
