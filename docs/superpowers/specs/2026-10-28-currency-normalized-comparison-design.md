# 到手价币种检测与汇率归一化比价设计

日期：2026-10-28

## 目标

1. 插件正确检测到手工价币种；Amazon.com 使用 USD，数据库原样保存美元金额。
2. 比对分析前将非人民币金额按服务器最新每日汇率换算为人民币，禁止不同币种直接混算。
3. 服务器每日拉取汇率并持久化缓存，定时不可用时提供按需更新与最近成功值回退。
4. 插件版本升级为 1.1.0 并重新打包。

## 数据口径

- `currency` 继续作为展示价、到手价和优惠金额的共同币种，金额为该币种的整数分。
- 插件依据平台规则及页面币种文本规范化为 ISO 4217 大写代码；Amazon.com 固定为 USD，淘宝、天猫、京东固定为 CNY。
- 服务端继续保存原币金额，不在入库时换算，不修改既有历史记录。
- 比价取展示价、缺失时回退到手价的现有规则不变；取价后将美元分值乘以 USD/CNY 汇率，再进入均值、价差、分组及统计检验。CNY 汇率为 1。
- 结果中保留原币观测，并明确标注“人民币折算价”、汇率、汇率日期和来源。浏览器本地留存的观测仍为原币金额。

## 汇率服务与缓存

- 新增独立汇率模块及 `exchange_rates` 表：基础币种、目标币种、每单位基础币对应的目标币汇率、汇率实际日期、来源、更新时间；基础币与目标币联合唯一。
- 使用 Frankfurter 的 `https://api.frankfurter.app/latest?from=USD&to=CNY` 每日 ECB 参考汇率，无需 API Key；实现中设置短超时并校验 HTTP 状态、JSON 结构、实际日期及正数有限汇率。
- 提供需 `X-User-Id` 鉴权的 `GET /api/exchange-rates/latest?base=USD&quote=CNY`；CNY/CNY 直接返回 1。当前仅要求 USD/CNY，其他不支持组合返回明确错误。
- 若当天尚无成功拉取记录，接口先按需拉取并写入数据库；成功缓存当日不再访问外部源。
- 外部请求失败时，返回最近一次成功缓存并设置 `stale=true`；无任何可用缓存时返回 503，不使用硬编码汇率。
- Vercel 配置每日 UTC 定时刷新；常驻服务通过现有后台任务体系每日刷新。定时路由复用同一服务函数，避免两套缓存逻辑。

## 看板流程

1. 用户取得本机商品的远端观测后，看板检测观测中实际使用的币种。
2. 全部为 CNY 时直接分析；含 USD 时先请求服务器汇率，成功后统一换算。
3. 汇率不可用则停止该商品分析并展示错误，不生成混币结论；其他商品的已有结果保留。
4. 每次分析使用同一响应中的汇率，结果展示该汇率及实际日期；缓存回退时明确显示“最近成功汇率”。

## 测试与版本

- 插件：Amazon 到手价为 USD，国内平台为 CNY；`manifest.json` 为 1.1.0，zip 内一致。
- 汇率：成功入库、当日缓存命中、请求失败回退、无缓存 503、非法上游响应、同币汇率、鉴权。
- 看板：USD 金额换算后参与分析，CNY 不变，汇率信息展示，失败不混算；脚本语法验证。
- 运行完整回归测试后提交并推送。

## 非目标

- 不做实时行情、多历史日期汇率选择或银行实际结售汇报价。
- 不把数据库中的 Amazon 原始美元金额改写为人民币。
- 不修改现有分析阈值、匿名化规则或本机商品匹配范围。
