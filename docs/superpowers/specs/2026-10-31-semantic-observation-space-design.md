# 分类语义三维观测空间设计

日期：2026-10-31  
状态：方案一已确认，书面设计待审阅  
分支：`feat/unified-balance-ui`

## 1. 目标与范围

重构 `/space` 的三维表达，使“商品是什么”决定语义平面位置，“何时采集”决定高度，“谁采集”决定点的颜色，“当前两用户对比是否值得关注”决定对比连线和包围圆的颜色。

采用已确认的方案一：**固定分类锚点为主，本地确定性商品名称向量为辅**。分类负责全局结构，名称分词和字符 n-gram 只在小类内部产生小幅分散，不再让高维特征哈希主导整个空间。

保留现有数据请求、匿名与管理员鉴权、筛选、搜索、点选、详情、时间播放、既有关系图层、双用户价格序列、CSV 导出、2D／表格视图和演示数据入口。不引入前端框架、外部模型服务、CDN 或新的统计推断结论。

本次同步的是看板 `lab.html` 的本地均价对比结论与三维空间的“当前双用户对比”可视结果。后端既有的中位数统计、`PRICE_GAP` 关系、价差筛选和平台复现口径不在本次改写；界面需明确区分“当前可视对比（均价混合筛查）”与“全局中位数统计”，避免把两种口径混为一谈。

## 2. 视觉编码与坐标约定

- **X／Z：分类语义平面。** 大类固定锚点决定区域，小类固定锚点决定区域内位置，商品名称向量只提供小类内部的有限偏移。
- **Y：采集时间。** 完整数据集最早有效时间为 `y=0`，最晚有效时间映射到 `y=100`；时间始终沿纵轴向上。
- **点颜色：采集用户。** 同一 `user_pseudonym` 始终使用同一颜色，未知用户使用中性灰；不再按平台、分类或价差方向给点着色。
- **分类体积：暗色圆柱。** 大类和小类都沿 Y 轴延伸，只表达类别范围，不承担用户或结论颜色。
- **当前对比：红／黄／绿。** 选中的商品和两名用户的有效可比点之间增加连线，并用一个半透明圆包围这些点；连线和圆使用同一对比结论颜色。
- 移除红绿蓝三轴辅助线、旧业务坐标／特征投影切换和颜色维度切换。场景说明固定为“X／Z：分类语义平面；Y：采集时间（UTC）”。

点选后的高亮、非选中商品淡出、缺少可比价格时的虚线或描边提示继续保留。结论同时以文字和颜色呈现，不只依赖红绿差异。

## 3. 固定分类布局

### 3.1 分类来源

后端现有 `CATEGORY_TAXONOMY` 是唯一分类目录来源。在现有 `/api/space/points` 响应中原样附加 `category_taxonomy`，不新增接口，也不改变点、统计和关系字段。演示数据响应同步携带同一目录。

新增纯布局模块 `api/app/static/js/space-layout.js`，输入完整点集和分类目录，输出点坐标、分类锚点、圆柱参数与标签参数。筛选、搜索、播放和视图切换只改变可见性，不重新计算锚点或点坐标；只有载入或刷新完整数据集时才重建布局。

### 3.2 大类锚点

按分类目录的固定顺序，将大类放在 X／Z 平面的 4×4 网格中，单元间距为 80 个场景单位，网格整体以原点为中心；未使用单元保持为空。15 个现有大类均有稳定位置，未来新增大类先按目录顺序使用空位；超过 16 个时保持 4 列并在 Z 方向追加网格行，已有锚点坐标不变。

该布局优先保证大类之间有充足间距，不使用力导向布局，不因当前数据量、筛选或商品名称改变大类位置。

### 3.3 小类锚点

每个大类内部按目录顺序使用固定的 3×3 网格，小类锚点相对大类锚点在 X／Z 两个方向各偏移 `-16／0／16`。现有每个大类最多 9 个小类，均有固定位置。小类位置只依赖父类锚点和目录顺序，不依赖当前可见商品。

缺少有效分类的点归入“其他／无法判断／无法判断”；目录异常时使用该类的稳定锚点并保留既有待分类提示，不随机散落。

### 3.4 商品名称的局部向量

同一 `product_key` 使用一个稳定名称：取该商品完整观测中最新一条非空商品名；同名商品的每次观测共享完全相同的 X／Z 偏移，因此同商品点只沿时间轴分布。

名称处理完全在浏览器本地完成：

1. 小写并统一空白；优先使用 `Intl.Segmenter` 的中文词语分词，不支持时回退为空白分词。
2. 对规范化名称补充字符 2-gram 和 3-gram，保留中文、字母和数字特征。
3. 对词语与 n-gram 做固定种子的特征哈希，并通过两组固定随机符号投影得到二维向量；该投影只保留局部名称差异，不宣称具有 PCA、t-SNE 或 UMAP 的全局语义。
4. 将二维向量限制在以小类锚点为圆心、半径 4 个场景单位的圆内。同名商品位置一致；名称越相似，局部偏移越接近，但任何名称都不能把商品推出所属小类区域。

最终位置为 `小类锚点 + 受限名称偏移`。不再按观测逐点添加随机抖动。

### 3.5 时间位置与 2D

时间归一化使用完整数据集的全局最早／最晚有效时间，筛选和播放不得改变比例。相同时间映射为 `y=50`；缺失或非法时间映射为 `y=0`，详情中继续显示原始缺失状态，播放过滤仍沿用现有规则。

2D 视图改为分类语义平面的俯视投影，即显示 X／Z、压平 Y；时间范围与播放仍控制可见点。表格字段、行点选和 CSV 内容不变。

## 4. 分类圆柱与原点标签

### 4.1 核心样本与半径

大类、小类圆柱都以各自固定锚点为圆心。按完整数据集中点到该锚点的 X／Z 距离升序排列，取最近的核心 90% 样本；核心半径是包围这些点所需的最小半径，再加少量视觉边距。离群点仍正常绘制，但允许位于暗圆柱之外。

对每个层级分别计算：

- 圆柱 X／Z 中心：固定分类锚点；
- 半径：覆盖该类别核心 90% 样本的最小同心圆半径；
- 底部：`y=0`；
- 顶部：核心样本中的最大 Y，单时间或空高度时使用最小可见高度；
- 空类别：不创建圆柱。

圆柱参数在完整数据载入时计算，筛选只控制对应类别是否显示，避免圆柱随播放跳动。

### 4.2 深度与透明度

使用开放端、双面、无深度写入的暗色透明圆柱，显式让数据点后绘制，圆柱不得挡住点选、悬停和点的颜色。

透明度由相机到分类锚点的距离平滑控制：缩小时、距离较远，圆柱稍清晰；放大进入分类时逐渐淡出。建议大类远／近不透明度为 `0.14／0.015`，小类为 `0.11／0.01`，中间使用平滑插值。不使用泛光、实心填充或高亮霓虹。

### 4.3 类别文字

大类和小类名称直接锚定在各自分类锚点的 `y=0` 平面，而不是堆在屏幕侧边图例中。使用本地 Canvas 生成文字纹理，不加载外部字体。

- 大类文字更大，小类文字较小，均保持清晰的中文字号和适度对比；
- 文字使用朝向相机的轻量标签，位置始终留在时间原点平面；
- 缩放时限制屏幕像素大小，避免远处过大、近处失控；
- 小类标签在过密时按距离淡出，大类标签优先保留；选中商品所属小类标签始终保留。

## 5. 三向无界网格与移动

移除固定 `GridHelper` 和 `AxesHelper`，改为三组正交的低对比网格：X／Y、X／Z、Y／Z。网格使用相同中性色，不为任何轴设置红绿蓝颜色。

网格以 `OrbitControls.target` 为中心按步长吸附并随移动重建或在着色器中偏移，远处逐渐淡出，不显示矩形边界。根据缩放层级在十进制步长间平滑切换，避免近处过密、远处闪烁。WASD 不设置空间硬边界，因此“无界”指导航与视觉参考不截断，而非创建无限几何体。

保留 OrbitControls 的拖动旋转、滚轮缩放、右键平移和阻尼，新增：

- **W／S：** 沿相机朝向在 X／Z 平面的投影前后移动；
- **A／D：** 沿相机右向量在 X／Z 平面的投影左右移动；
- 相机和 `controls.target` 同步平移，保持当前观察方向与缩放距离；
- 按住按键时按帧时间连续平滑移动，窗口失焦或页面隐藏时清空按键状态；
- 仅在 3D 视图且事件目标不是输入框、下拉框、文本域或可编辑元素时响应，忽略 Ctrl／Meta／Alt 组合键；
- 2D 视图不启用 WASD，移动端继续默认 2D 和触控操作。

场景操作说明更新为“拖动旋转 · 滚轮缩放 · WASD 平移 · 右键平移 · 点击商品突出”。减少动态效果偏好下取消移动惯性，但保留用户主动导航。

## 6. 当前双用户对比

### 6.1 参与对比的点

沿用现有交互：先点选商品，或筛选到单一商品，再选择两个不同的用户假名。只有同时满足以下条件的点进入当前对比：

1. 属于当前 `product_key`；
2. 属于用户 A 或 B；
3. 通过当前全部筛选和时间播放位置；
4. 具有有效的 `normalized_price_cents`，统一使用人民币可比价。

没有选中商品、用户相同、任一侧无点或没有有效可比价时，不绘制对比连线和包围圆，侧栏显示具体原因。原始币价格不得与人民币或其他币种混算。

### 6.2 连线

对 A、B 两侧的有效可比点建立跨用户连线；同用户点之间不新增当前对比线。所有线使用第 6.4 节的同一结论颜色，并保持较低不透明度，数据点始终位于连线上方。

为避免密集数据产生不可用的线段数量，按观测 ID 排序生成候选对，最多绘制前 1000 条；截断时在对比面板明确显示“仅绘制前 1000 条”，统计仍使用全部有效点，不随线条截断而截断。

既有 `PRICE_GAP` 等关系图层继续独立工作。新增“当前对比”图层开关，默认开启，同时控制本节的连线和包围圆，不改变旧关系图层的语义。

### 6.3 半透明包围圆

包围圆使用沿 Y 轴朝向相机的竖直平面：圆心为当前对比点三维包围盒的中心，平面横轴为相机右向量在 X／Z 平面的投影。每次相机移动后，将对比点投影到该平面，计算覆盖全部投影点的最小同心圆半径，并加少量视觉边距。

该圆随观察方向更新，但始终包含全部当前对比点；使用半透明填充和细边线，无深度写入，点与连线后绘制。圆的颜色与连线、侧栏结论一致。由于同商品共享 X／Z 坐标，圆主要表达这组跨用户观测的时间覆盖范围，而不是新增一个业务指标。

### 6.4 共享混合判定规则

新增纯函数模块 `api/app/static/js/comparison-rule.js`，统一输入两名用户的有效人民币价格序列，输出低价侧、高价侧、均价、样本量、绝对差、相对低价侧百分比、阈值命中情况、结论和可读原因。

默认阈值固定为：

- 绝对均价差：**≥ 5 元**；
- 相对均价差：**≥ 低价侧均价的 5%**；
- 充分样本：两侧各 **≥ 3 条**。

结论规则：

| 条件 | 结论 | 颜色 |
| --- | --- | --- |
| 绝对差和相对差均达阈值，且两侧样本均 ≥3 | 疑似差异定价，具备初步参考价值 | 红 |
| 双阈值均达成但任一侧样本 <3 | 低置信疑似，小样本仅供参考 | 黄 |
| 只达到绝对差或相对差其中一个阈值 | 单一维度异常，需结合另一维度观察 | 黄 |
| 两个阈值均未达到 | 当前未见明显差异 | 绿 |

因此，低价商品即使相对比例很高，只要绝对差不足 5 元，就不会直接判红；高价商品只有绝对差达到 5 元、但相对差不足 5% 时，也只显示黄色。低价侧均价为 0 且高价侧大于 0 时，相对差按无穷大参与判断，界面显示“低价侧为 0”而不显示 `Infinity`；两侧均价均为 0 时相对差为 0。

`lab.html` 继续自动选择均价差最大的用户对，保留 Welch 检验、分组维度、本地留存与导出，但其主结论、徽章、解释文字、阈值说明和留存结果改用上述共享函数。三维空间使用同一个函数计算当前选定的 A／B，不再复制一套颜色判断。

### 6.5 对比面板

现有双用户价格序列保留，用户曲线颜色改为与三维点的用户颜色一致。面板新增：低价／高价侧、均价差（元）、相对差、两侧样本量、红黄绿文字结论，以及“≥5 元且≥5%，两侧各≥3”的口径说明。

该面板与连线、包围圆使用同一次计算结果，筛选或播放导致点集变化时同步更新。侧栏原有“价差统计与平台复现”明确标注为“全局中位数统计（后端研究口径）”，不冒充当前可视对比结果。

## 7. 用户颜色与图例

用户颜色由 `user_pseudonym` 的稳定哈希映射到既有低饱和辅助色板；同一用户在刷新、筛选和视图切换后颜色不变，未知用户固定为灰色。色板不足时允许不同用户复用颜色，但图例和详情始终显示假名，不以颜色作为唯一身份标识。

原颜色维度控件替换为“采集用户”图例，只列出当前可见用户及其颜色；选中 A／B 时突出对应图例项。分类不再占用点颜色，类别信息完全由位置、暗圆柱和原点标签表达。

## 8. 模块边界与数据流

- `space-layout.js`：固定分类锚点、名称局部向量、全局时间映射、核心圆柱参数；不依赖 Three.js。
- `comparison-rule.js`：均价汇总、混合阈值和红黄绿结论；同时供 `lab.html` 与空间页面使用，不依赖 DOM 或 Three.js。
- `space-core.js`：保留筛选和 CSV；删除旧业务坐标与特征投影职责。
- `space.js`：Three.js 场景、用户颜色、网格、圆柱、标签、对比几何、WASD 和现有交互编排。
- `space-mock.js`：提供与真实响应同形的分类目录和可验收的红黄绿对比样例。
- `space_api.py`：只在现有响应中附加固定分类目录，不计算名称向量，不改变既有统计。
- `lab.html`：以 ES 模块方式引入共享规则，现有 IIFE 状态与事件结构保持不变。

完整数据进入后先计算一次布局，再由筛选得到可见点；点坐标写入点云，分类参数写入圆柱与标签。当前商品、用户和过滤后的有效点进入共享比较函数，结论一次性驱动连线、包围圆和侧栏。相机移动只更新网格、圆柱透明度、标签和包围圆朝向，不重算业务坐标。

## 9. 错误、空状态与性能

- 无数据、待分类、汇率缺失、请求失败、管理员会话失效和演示数据继续沿用现有提示与重试路径。
- WebGL 不可用时保留 2D／表格和全部数据工作流，不因分类圆柱或文字纹理失败而阻断点选与导出。
- 缺少名称时名称偏移为 0；缺少有效分类时进入稳定的未知分类；缺少时间时按第 3.5 节处理。
- 缺价或币种不可比的点仍可按用户显示，但不进入当前均价对比，面板显示被排除数量。
- 单类别或单时间点不生成零尺寸几何，使用最小可见半径／高度；空类别不生成圆柱和标签。
- 点云和既有关系仍采用批量绘制；每个目录条目至多生成一个圆柱和一个标签，当前对比线最多 1000 条。对比线截断时必须提示，不能静默丢数据。
- 限制设备像素比，释放重建的几何体、材质和文字纹理；页面隐藏时停止动画、播放和按键移动。

## 10. 验证与成功标准

### 10.1 纯逻辑自动化

为布局和共享规则新增 Node 测试，至少覆盖：

- 大类／小类锚点与目录顺序稳定，筛选前后坐标完全一致，大类间距符合固定网格；
- 同商品各观测 X／Z 相同，同名商品偏移相同，所有名称偏移不超出小类半径；
- 时间使用完整数据集归一化，单时间、缺失时间和非法时间行为明确；
- 核心 90% 圆柱半径、空类别、单点和最小尺寸；
- 用户颜色对同一假名稳定；
- 共享规则的边界值：`5 元`、`5%`、每侧 `3` 条，双阈值、单阈值、小样本、零低价侧和缺价；
- 低价商品 `1 元 → 2 元` 即使相对差 100%，充分样本也只能为黄色；`100 元 → 106 元` 且两侧各 3 条时为红色；
- 当前对比只选跨用户有效点对，排序稳定，1000 条截断只影响绘制不影响统计；
- 看板与空间引入同一共享模块，演示数据与真实响应分类目录同形。

更新现有空间页面和计算测试，移除对旧坐标模式、颜色维度和三轴的断言，保留筛选、播放、CSV、点选与后端原统计口径的回归测试。

### 10.2 本地可视与交互验收

使用演示数据和本地真实数据分别验证：
