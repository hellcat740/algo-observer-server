# 商品已选规格采集设计

日期：2026-11-01

## 背景与目标

当前插件只保存平台商品 ID、商品名和价格。同一商品存在颜色、尺码、型号等多个选项时，观测无法说明价格对应的具体变体。本次为淘宝、天猫、京东和 Amazon.com 增加当前 SKU 标识及已选规格字段；拼多多不在本次范围内。

## 方案

采用“DOM 当前选中状态为主、URL／页面内嵌数据补充 SKU 标识”的方式。DOM 反映用户实际看到的选项，比只解析默认页面数据可靠；只保存 URL 中的 `skuId` 无法覆盖京东和 Amazon，也不提供可读规格。

新增上报结构：

```json
{
  "sku_id": "6291578435222",
  "selected_options": [
    {"name": "颜色分类", "value": "Ryzen 3 3200G散片"},
    {"name": "尺码", "value": "L【体重110-125斤】"}
  ]
}
```

两个字段均可空。无规格商品返回空数组或 `null`，不影响原采集、上报和统计流程。规格名称与值保存页面公开文本，不采集额外用户信息。

## 插件实现

- 淘宝／天猫：遍历 `skuItem--` 规格组，读取组名及 `isSelected--` 选项；补充常见旧版选择器。
- 京东：支持旧版 `.sku-choose`／`.item` 与新版规格容器，读取每组选中项，避免把服务、促销等非 SKU 区域混入。
- Amazon：读取 `#twister` 内各变体组，支持选中按钮、列表项及下拉框；ASIN 继续兼容 `/dp/` 与 `/gp/product/`，优先使用当前 `ASIN`／URL 标识。
- 从 URL 和页面数据提取 `sku_id`；URL 没有 SKU 时仍保存可读选项。
- 自动采集去重键由单独 `productId` 改为商品 ID 加 SKU／规格摘要，避免不同变体在十分钟窗口内被错误去重。
- 后台映射与本地记录保留 `sku_id`、`selected_options`，失败重试不会丢失字段。
- 发布插件版本升级为 1.2.0，并同步下载页版本信息。

## 后端与兼容

- `ObservationIn` 接收可空 `sku_id` 和 `selected_options`；每个选项包含非空 `name`、`value`。
- `Observation` 使用跨 SQLite／PostgreSQL 的可空 JSON 列保存选项，字符串列保存 SKU。
- 启动时轻量迁移为旧表补列，旧数据为 `NULL`。
- 清洗层做长度、数量和文本类型限制，防止异常大 payload；合法字段原样保留。
- `ObservationOut`、管理端详情与同步／导出所复用的观测序列化链路包含新字段。
- 商品分类缓存仍按原商品身份工作，不因规格变化额外调用模型；本次不改变既有统计分组口径。

## 错误处理

- 页面没有规格、规格尚未渲染或选择器失效：字段为空，价格采集继续。
- 找到规格组但无明确选中项：不猜测默认项，不上报未选值。
- 多组规格：保持页面顺序，逐组保存，不能只保存最后一组。
- 非法或超长字段：按现有清洗约定降级／提示，不泄露完整页面脚本。

## 测试与验证

1. 为四平台增加多规格选中、无选中、无规格和 SKU 提取回归测试。
2. 验证上报映射、API 入库／输出、SQLite 轻量迁移与旧记录兼容。
3. 验证自动采集不同 SKU／选项不会被错误去重。
4. 运行插件相关测试及完整测试套件。
5. 使用真实浏览器验证用户提供的淘宝、天猫页面，并从京东热卖聚合页进入商品详情验证；选择 Amazon 示例商品验证变体。页面不可访问或结构变化时如实记录，不用固定测试替代真实验证结论。
